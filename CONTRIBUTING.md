# Contributing

**English** | [繁體中文](CONTRIBUTING.zh-TW.md)

Thanks for helping! This project is for learning, so clarity beats cleverness. Questions or ideas: [open an issue](https://github.com/BartonChenTW/grid-balancing-game/issues/new/choose) (English or 中文) or email [barton.chen.energy@gmail.com](mailto:barton.chen.energy@gmail.com).

## Ground rules

- **No build step and no dependencies.** Plain HTML, CSS and JavaScript modules that run as static files.
- **Keep the simulation pure.** `js/sim.js`, `js/units.js`, `js/auto.js`, `js/fleet.js`, `js/score.js`, `js/economics.js` and the validation in `js/scenarios.js` take state in and return state out, with no DOM and no `Math.random` (use the seeded RNG).
- **No magic numbers.** Tunable values go in `js/config.js` or `data/unit-types.json`.
- **All UI text goes in `js/strings.js`** and its translation `js/strings-zh-TW.js`, so both languages stay complete.
- **Explain approximations.** When you simplify the physics, add a comment saying what is approximate.
- Run `npm test` before sending a change. If you touch data or tuning, also run `node tools/balance-report.js` (and `hard`) and check that every scenario × day is still winnable.

## Add or improve data

The most valuable contribution is **real data**.

- **Day shapes** (`data/days.json`, generated by `tools/make-days.js`) are placeholders. Measured Taipower 10-minute system load, solar and wind for typical days (summer and winter weekday and weekend, Lunar New Year, a typhoon day) would replace them. Profiles can have any length that divides 1440 (24, 48, 96, 144…). `load` is a fraction of the day's peak, `peakRatio` is the day's peak as a fraction of the annual peak, `solar` and `wind` are fleet capacity factors (0–1).
- **Scenarios** (`data/scenarios/*.json`) describe a fleet: one entry per technology with its total `maxMW` and how many identical units it has (`count`; storage, hydro, demand response, solar and wind are one unit). Wind can give its `offshoreShare` (0–1) for the cost estimate. Add the file id to `data/scenarios/index.json` and fill in `dataStatus` (`partial`, `placeholder`), `dataNotes` and `sources` honestly.

  ```json
  { "type": "coal", "maxMW": 19309, "count": 27 }
  { "type": "hydro", "maxMW": 2124, "energyMWh": 15000, "initialState": "online", "initialPct": 10 }
  { "type": "wind", "maxMW": 4517, "offshoreShare": 0.78 }
  ```
- **Unit types** (`data/unit-types.json`): cold start-up (`startupMin`, to standby) and `syncMin` (standby to online; leave it out for types without standby), shut-down minutes, ramp %/min, minimum stable %, inertia constant H, fuel cost and CO₂ per MWh, `standbyCostPerMWh`, `fuel` group, typical `unitMW`, Auto role (`autoRole`), plus flags such as `storage`, `energyLimited`, `activationLimited`, `variable`, `fastResponse`, `mustRun`, `restartable`.
- **Build costs** (also in `data/unit-types.json`): `capexEURPerKW`, `lifeYears`, and for batteries `capexEURPerKWh` and `energyLifeYears`, for wind `capexOffshoreEURPerKW`. They follow the [Taiwan PyPSA-Earth model](https://bartonchentw.github.io/pypsa-earth/) (technology-data 2030 projections, 2013 euros). An optional `capexSpreadPct` gives a technology its own uncertainty instead of the default ±30% in `js/config.js`.

The loader validates every file and names the exact field that is wrong, so the fastest check is to open the game or run `npm test`.

### Events

Scenarios and days can list events:

```json
{ "timeMin": 547, "type": "trip", "unitType": "coal", "lossMW": 2600, "note": "hsinta2022" }
{ "timeMin": 600, "type": "trip", "unitType": "gasCcgt", "units": 2 }
{ "timeMin": 780, "type": "clouds", "factor": 0.45, "durationMin": 50 }
{ "timeMin": 840, "type": "windCutout", "factor": 0.1, "durationMin": 480, "rampMin": 120, "warnMin": 240 }
{ "timeMin": 900, "type": "windLull", "factor": 0.35, "durationMin": 90 }
{ "timeMin": 960, "type": "demandSurge", "factor": 1.05, "durationMin": 120 }
```

A trip disconnects online units of `unitType`: `units` of them, or as many as needed to lose `lossMW`. `note` refers to a `note.<id>` string in `js/strings.js`. `warnMin` announces the event in advance and adds it to the forecast. Random accidents are configured in `js/config.js` (`events.random`).

## Translate

Each language is a table with the same keys as the `en` table in `js/strings.js`; see `js/strings-zh-TW.js`. Add a file, import it in `strings.js`, and register it in `TABLES` and `LANGUAGES`. Scenario and day text can be translated with `scenario.<id>.name`, `scenario.<id>.description`, `scenario.<id>.dataNotes`, `day.<id>.name` and `day.<id>.description`. Missing keys fall back to English.

Repository documents come in pairs: `README.md` / `README.zh-TW.md`, `CONTRIBUTING.md` / `CONTRIBUTING.zh-TW.md`, `CHANGELOG.md` / `CHANGELOG.zh-TW.md`. Please update both when you change one.

## Release

1. Bump the version in `js/version.js` (with the release date) and `package.json`.
2. Add an entry at the top of `CHANGELOG.md` and `CHANGELOG.zh-TW.md` (`## X.Y.Z — YYYY-MM-DD`); `npm test` checks that they agree.
3. Commit, tag and push: `git tag -a vX.Y.Z -m "…"` then `git push origin main --tags`.
4. Check that the live site shows the new version in its header. If GitHub Pages did not rebuild, run `gh api -X POST repos/BartonChenTW/grid-balancing-game/pages/builds`.

## Test locally

```sh
npm start   # http://localhost:8000
npm test
```

Add `?demo` to the URL to let the scripted operator (`tools/autopilot.js`) play.
