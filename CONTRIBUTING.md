# Contributing

Thanks for helping! This project is for learning, so clarity beats cleverness.

## Ground rules

- **No build step and no dependencies.** Plain HTML, CSS and JavaScript modules that run as static files.
- **Keep the simulation pure.** `js/sim.js`, `js/units.js`, `js/score.js` and the validation in `js/scenarios.js` take state in and return state out, with no DOM and no `Math.random` (use the seeded RNG).
- **No magic numbers.** Tunable values go in `js/config.js` or `data/unit-types.json`.
- **All UI text goes in `js/strings.js`** so it can be translated.
- **Explain approximations.** When you simplify the physics, add a comment saying what is approximate.
- Run `npm test` before sending a change. If you touch data or tuning, also run `node tools/balance-report.js` (and `hard`) and check that every scenario × day is still winnable.

## Add or improve data

The most valuable contribution is **real data**.

- **Day shapes** (`data/days.json`, generated by `tools/make-days.js`) are placeholders. Measured Taipower 10-minute system load, solar and wind for typical days (summer and winter weekday and weekend, Lunar New Year, a typhoon day) would replace them. Profiles can have any length that divides 1440 (24, 48, 96, 144…). `load` is a fraction of the day's peak, `peakRatio` is the day's peak as a fraction of the annual peak, `solar` and `wind` are fleet capacity factors (0–1).
- **Scenarios** (`data/scenarios/*.json`) describe a fleet. Add the file id to `data/scenarios/index.json`. Keep 6–15 units so the screen stays playable, and fill in `dataStatus` (`partial`, `placeholder`), `dataNotes` and `sources` honestly.
- **Unit types** (`data/unit-types.json`): start-up and shut-down minutes, ramp %/min, minimum stable %, inertia constant H, cost and CO₂ per MWh, plus flags such as `storage`, `energyLimited`, `activationLimited`, `variable`, `fastResponse`, `mustRun`, `restartable`.

The loader validates every file and names the exact field that is wrong, so the fastest check is to open the game or run `npm test`.

### Events

Scenarios and days can list events:

```json
{ "timeMin": 547, "type": "trip", "unit": "Gas CCGT A", "fraction": 0.4, "note": "hsinta2022" }
{ "timeMin": 780, "type": "clouds", "factor": 0.45, "durationMin": 50 }
{ "timeMin": 840, "type": "windCutout", "factor": 0.1, "durationMin": 480, "rampMin": 120, "warnMin": 240 }
```

`note` refers to a `note.<id>` string in `js/strings.js`. `warnMin` announces the event in advance and adds it to the forecast.

## Translate

Each language is a table with the same keys as the `en` table in `js/strings.js`; see `js/strings-zh-TW.js`. Add a file, import it in `strings.js`, and register it in `TABLES` and `LANGUAGES`. Scenario and day text can be translated with `scenario.<id>.name`, `scenario.<id>.description`, `scenario.<id>.dataNotes`, `day.<id>.name` and `day.<id>.description`. Missing keys fall back to English.

## Test locally

```sh
npm start   # http://localhost:8000
npm test
```

Add `?demo` to the URL to let the scripted operator (`tools/autopilot.js`) play.
